# Channel Gate Bot — бот-привратник с подтверждением интереса для закрытого канала

Шаблон №1 из линейки ботов. Заявка на вступление в канал не одобряется автоматически — сначала бот
присылает пользователю оффер («доступ и бонус уже готовы для вас, осталось
подтвердить») с кнопкой-ссылкой на диалог с ботом. Это решает сразу
две задачи:
- отсеивает спам-ботов, массово подающих заявки на вступление —
  скрипт не реагирует на психологически выстроенный оффер, а человек жмёт;
- даёт боту подтверждённое право писать пользователю в будущем.

**Важная деталь реализации.** Кнопка — не обычная inline-кнопка (callback),
а кнопка-ссылка вида `t.me/<бот>?start=confirm_<id>`. Это принципиально:
Telegram открывает боту диалог с пользователем только если пользователь
САМ отправил боту настоящее сообщение (например, `/start`) — обычный клик
по callback-кнопке для этого не считается, хотя выглядит так же для
человека. Кнопка-ссылка при нажатии автоматически отправляет
`/start confirm_<id>` как настоящее сообщение, поэтому право писать
пользователю закрепляется надёжно.

Если пользователь не отвечает вовремя, заявка **не отклоняется сразу** —
бот присылает до `MAX_REMINDER_ATTEMPTS` напоминаний (каждое новым
сообщением, чтобы пришло уведомление) и только после этого отклоняет.
Это защищает от потери тёплых лидов, которые просто не успели открыть
телефон вовремя.

После подтверждения пользователь получает бонус в ЛС и попадает в список
получателей рассылки. Администратор видит статистику и может сделать
массовую рассылку по всем подтверждённым пользователям.

## Кому продавать

Владельцам платных Telegram-каналов, клубов, курсов — всем, кто хочет
защититься от накрутки ботами и держать надёжный канал связи с реальной
аудиторией для рассылок и объявлений.

## Структура проекта

```
bot.py                      точка входа
config.py                   чтение и валидация .env
states.py                   FSM-состояния (рассылка)
database/db.py               работа с SQLite (aiosqlite)
handlers/join_requests.py   подтверждение интереса, напоминания, одобрение/отклонение заявок
handlers/admin.py            админ-панель, статистика, рассылка
handlers/user.py             ответ обычным пользователям
keyboards/admin_kb.py         инлайн-клавиатуры
```

## Запуск (локально, в PyCharm)

1. Создай виртуальное окружение и установи зависимости:
   ```
   pip install -r requirements.txt
   ```
2. Скопируй `.env.example` в `.env` и заполни:
   - `BOT_TOKEN` — получи у [@BotFather](https://t.me/BotFather)
   - `ADMIN_IDS` — твой Telegram ID (узнать можно у [@userinfobot](https://t.me/userinfobot))
   - `CONFIRM_TIMEOUT_SECONDS` — необязательно, по умолчанию 300 секунд. Для теста
     удобно временно поставить 10-15, чтобы не ждать по 5 минут между напоминаниями
   - `MAX_REMINDER_ATTEMPTS` — необязательно, по умолчанию 2
3. Добавь бота администратором в свой канал с правом
   **«Приглашение пользователей по ссылке»** (Invite Users via Link) —
   это же право нужно и для одобрения, и для отклонения заявок.
4. Запусти:
   ```
   python bot.py
   ```

## Как это тестировать

1. Создай в канале инвайт-ссылку с включённой опцией **«Заявки на вступление»**.
2. Подайте заявку с другого аккаунта — бот пришлёт оффер с кнопкой в личку.
3. Нажми кнопку — заявка должна одобриться, придёт бонус.
4. Чтобы проверить напоминания: подай новую заявку, но не нажимай кнопку.
   Выставь `CONFIRM_TIMEOUT_SECONDS=10` в `.env` для быстрого теста — через
   10 секунд должно прийти напоминание (новым сообщением), ещё через 10 —
   второе, последнее, а затем заявка отклонится.
5. Команда `/start` от твоего (админского) ID должна открыть панель управления.
6. В статистике проверь, что подтверждённый пользователь попадает
   в категорию «Подтвердили интерес и подписаны».

## Известное ограничение

Таймеры напоминаний хранятся в памяти процесса (через `asyncio.sleep`), а не
в базе данных. Если перезапустить бота, пока кто-то ждёт напоминания — его
таймер потеряется, и заявка так и останется в статусе `pending`, пока
человек либо не ответит сам, либо не появится доработка с восстановлением
таймеров из БД при старте. Для MVP и тестов это не критично, но для боевой
продажи клиенту стоит иметь это в виду (не перезапускать бота часто вручную).

## Что можно добавить для более дорогой версии

- Восстановление таймеров напоминаний из БД после перезапуска бота
- Разные тексты оффера под конкретную нишу канала (сейчас текст общий)
- Настраиваемые тексты и кнопки через админ-панель, без правки кода
- Несколько уровней доступа (разные каналы под разные тарифы)
